Firebase: checking…

0 · Machine check

Rough check only — CPU, RAM, disk, Docker, and the CLI tools Setup needs. Not required before Run setup, just saves a confusing failure later.

    1 · Environment

    2 · Agent & model

    Grades diagnosis quality against a fixed checklist — kept the same across every agent/model you try here, so results stay comparable to each other. Changing it is fine to experiment with, but the number won't compare to anyone else's runs.

    3 · Problems

    Batching runs the selected problems a few at a time instead of one long sequential queue — each batch finishes and logs a summary before the next one starts, so a stuck run only costs you one batch, not the whole set. 0 runs everything in one go.

    4 · Keys & Firebase

    Auto-detected on startup from ReliOps/.env — a GOOGLE_APPLICATION_CREDENTIALS path, or the key's JSON pasted directly into FIREBASE_SERVICE_ACCOUNT_JSON / SERVICE_ACCOUNT_KEY, no path needed at all. The field above and the Connect button are only for overriding that.

    If the whole team points this at the same Firebase project (one shared key), results show up for everyone in one place. That key has full access for anyone who has it — "Your name" above just labels who ran what, it isn't an access control. See the README's "Shared results" section.
