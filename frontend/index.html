0 · Machine check

Rough check only — CPU, RAM, disk, Docker, and the CLI tools Setup needs. Not required before Run setup, just saves a confusing failure later.

    2 · Agent & model

    Grades diagnosis quality against a fixed checklist — kept the same across every agent/model you try here, so results stay comparable to each other. Changing it is fine to experiment with, but the number won't compare to anyone else's runs.

    Free text. Runs with the same agent, model, action space, judge and label are grouped together in the Results tab, so two variants of the same agent never get averaged into one number. Change the label whenever you change the agent's code or prompt.

    The two classes are never mixed in a table. Use frozen only for runs you intend to report.

    3 · Problems

    Batching runs the selected problems a few at a time instead of one long sequential queue — each batch finishes and logs a summary before the next one starts, so a stuck run only costs you one batch, not the whole set. 0 runs everything in one go.

    For a real n on noisy metrics like time-to-diagnose. Each repeat is its own row below, so a problem that happens to take 30+ minutes doesn't look stuck — you can see which specific repeat is still running.

    4 · Keys & Firebase

    "Custom…" is for anything not in the list — e.g. a self-hosted open-weight model's own key or endpoint token. Type whatever env var name SREGym/the agent expects to read.

    Read straight from this project's own .env (same file as the model key above, not any .env inside the separately-cloned ReliOps folder) — a GOOGLE_APPLICATION_CREDENTIALS path, or the key's JSON pasted directly into FIREBASE_SERVICE_ACCOUNT_JSON / SERVICE_ACCOUNT_KEY. Nothing to paste or click here: put it in .env and the status pill at the top updates on its own within a few seconds.

    If the whole team points this at the same Firebase project (one shared key), results show up for everyone in one place. That key has full access for anyone who has it — "Your name" above just labels who ran what, it isn't an access control. See the README's "Shared results" section.

    Run

    Stop finishes whichever problem is currently running, records its result, then skips the rest — nothing mid-run is killed. Click Run test(s) again later to pick up where you left off.

    Freeze a campaign
    
      
    Records exactly what a measured run is allowed to be: agent code commit, model, action space,
        judge, config label, problem set and repeat count. Uses the settings currently chosen on the Run tab
        (agent, model, judge, label, selected problems, repeat count). Needs the ReliOps clone's
        agent/ and scripts/ committed, and refuses runs that do not match afterwards.

    Cells are (problem, repeat). With five laptops, give each the same campaign and its own
        slice (1 of 5 ... 5 of 5): slices never overlap, and a cell that crashed (no known outcome) is run again.
        Progress streams into the Run tab's live log.

    Re-judge with another model
    
      
    Grades the stored diagnosis text again with a different judge, using SREGym's own judge and
